# Gary Home code audit — 22 October 2026

Audited commit: `0ba5a4eed0bcc9d8fe5e28a27619013bbc9b62c4` in `gary-home/`.

The highest priorities are the password-reset account race and the enquiry trigger's interference with administrative deletion. The existing test suite passes, but isolated reproductions demonstrate both defects and additional synchronization and CRM problems.

This was a source review with local Postgres and React reproductions. No application source, live database, account configuration, or GitHub commit was changed.

## Findings

### 1. P1 — Password reset can change a different account after a session switch

Location: [password-reset.tsx:8](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/password-reset.tsx:8).

The form checks that `getSession()` returns some session, then independently calls `client.auth.updateUser({ password })`. It never binds the operation to the account originally checked and does not invalidate the flow when Auth changes. Unlike the profile and Studio mutations, this path does not use an identity/generation guard.

Reproduction: pause the first session read for account A, switch the shared Auth client to a valid session for B, then resolve the old A read. The real component calls `updateUser` against B and subsequently signs B out. The installed SDK's `_updateUser` obtains its JWT from the current session at invocation time, so the earlier session read does not bind that request.

Impact: a password intended for A can be applied to B. This requires switching between valid sessions in the same browser.

Recommended correction: bind password changes to the verified recovery identity and token, invalidate recovery state on identity changes, and ensure the actual Auth update cannot select a different shared session while awaiting SDK initialization or locking. Add an account-switch regression test for the password flow.

### 2. P1 — The cancellation guard blocks administrative user and property deletion

Location: [customer portal migration:108](/Users/skycastle3/Desktop/gary_home_website/gary-home/supabase/migrations/20261021201948_customer_portal.sql:108).

The trigger runs before every enquiry update. In an administrative SQL context with no `auth.uid()`, `private.is_editor()` is false and the trigger raises `42501`. Foreign-key `ON DELETE SET NULL` actions also update enquiries, including deletion of their Auth user or property.

Reproduction: apply the complete `setup.sql` in PGlite, create a customer and an enquiry referencing a published property, then execute either administrative delete. Both fail with `Customers may only cancel their own active viewing requests.` The user remains present after the failed delete.

Impact: normal administrative cleanup and account-deletion operations fail whenever the affected row has enquiries.

Recommended correction: distinguish trusted referential-maintenance operations from customer API updates while retaining the customer cancellation restrictions. Ship a forward migration and test both parent-deletion cases under administrative roles.

### 3. P2 — Direct Data API inserts bypass the form's abuse controls

Locations: [anonymous insert grant:120](/Users/skycastle3/Desktop/gary_home_website/gary-home/supabase/migrations/20261021152453_gary_home_cms.sql:120), [submission policy:96](/Users/skycastle3/Desktop/gary_home_website/gary-home/supabase/migrations/20261021201948_customer_portal.sql:96), [API limiter:36](/Users/skycastle3/Desktop/gary_home_website/gary-home/app/api/enquiries/route.ts:36).

The publishable key and project URL are intentionally public, and `anon` can insert directly into `enquiries`. The honeypot, same-origin check, body validation, and five-per-ten-minute limit exist only in `/api/enquiries`. Direct REST inserts do not execute that route.

Reproduction: the deployed SQL accepted 20 valid anonymous enquiry rows in one local Postgres statement. The same table privileges support bulk inserts through PostgREST. This audit sent no spam to the live project.

Impact: an automated client can fill the inbox and consume database resources without encountering the application limiter. The current RLS still protects private reads and staff fields.

Recommended correction: make every accepted submission pass through a trusted validation/anti-abuse boundary and enforce durable limits there. Retain authenticated ownership when restructuring the insert path. A stronger limiter only on the current Next/Vinext route would leave the direct insert path open.

### 4. P2 — Importing a shortlist can undo a later removal in the UI

Location: [site-context.tsx:252](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/site-context.tsx:252).

`importSaved()` does not reserve the affected IDs in `savedFlight` or `pendingSaved`. Property heart buttons therefore remain enabled during import. The import completion unconditionally merges all imported IDs into the current client state.

Reproduction: start an import of an already-saved home and delay its response after the database operation commits. Remove that home while the import response is pending. The database correctly ends with no saved row; the late import response adds the home back to the UI. The import reports success with the UI and database disagreeing.

Recommended correction: coordinate imports and individual toggles per property, or reconcile against an authoritative read after all conflicting operations settle. Add a response-reordering test.

### 5. P2 — CRM drafts disappear after same-user reauthentication

Location: [customer-manager.tsx:14](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/customer-manager.tsx:14).

The selected customer and unsaved private notes live only in `CustomerManager` state. A terminal session loss makes `AdminPage` return its sign-in screen and unmounts this component. Restoring the same staff account creates a fresh manager with no draft.

Reproduction: open Customers, start a record and type private notes, emit sign-out/session loss, then restore the same owner session. The original draft is gone. Existing Studio property/settings draft coverage does not cover this nested CRM state.

Recommended correction: retain drafts in account-scoped memory above the authentication gate, clear them on explicit sign-out/account changes, and restore them only for the same account. Also handle unsaved CRM drafts when leaving the Customers tab.

### 6. P2 — CRM Refresh does not refresh incoming enquiry contacts

Location: [customer-manager.tsx:27](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/customer-manager.tsx:27).

The directory merges profiles, CRM records, and `site.enquiries`. Its Refresh button reloads only the first two inputs. New guest enquiries therefore remain absent from the directory and enquiry history until a separate full CMS refresh or wake event occurs.

Reproduction: load an empty directory, add a new guest enquiry at the mocked backend boundary, and click the CRM Refresh button. The contact remains absent. Calling the existing shared `refresh()` makes the same contact appear.

Recommended correction: refresh all three directory inputs together and retain the existing generation/version guards.

### 7. P2 — Unpaginated reads silently omit records beyond the API row cap

Locations: [CMS reads:63](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/site-context.tsx:63), [CRM reads:28](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/customer-manager.tsx:28), [public catalogue read:23](/Users/skycastle3/Desktop/gary_home_website/gary-home/lib/server.ts:23).

These list queries fetch a single response, then compute counts, filtering, and search in the browser. They never request subsequent ranges or report truncation. Supabase's platform default is a maximum of 1,000 returned rows, configurable per project. [Supabase row-limit documentation](https://supabase.com/docs/reference/python/select).

Reproduction: an isolated React test simulated a 1,000-row API cap with 1,001 CRM records. The last stored contact could not be found by the directory search. The actual target project's configured cap was not inspected.

Impact: after exceeding the project's cap, older leads and follow-ups disappear from search and counts. Public catalogue filtering and the sitemap can also omit listings once the catalogue exceeds that cap.

Recommended correction: use server-side filtering, deterministic pagination, and explicit total counts. Fetch every required page for complete exports and sitemap generation.

### 8. P3 — Missing property URLs return HTTP 200

Locations: [property route:8](</Users/skycastle3/Desktop/gary_home_website/gary-home/app/homes/[slug]/page.tsx:8>), [detail fallback:14](/Users/skycastle3/Desktop/gary_home_website/gary-home/components/property-detail.tsx:14).

The route imports `notFound` but never calls it. The client renders a missing-listing message inside a successful page response.

Reproduction: `GET /homes/audit-missing-home-20261022` returned HTTP 200 with the missing-home message and `Home not found` metadata.

Recommended correction: validate the slug/public availability on the server and return the framework's 404 response. Preserve the useful bilingual recovery links in the not-found UI.

## Dependency patching observations

The lockfile installs Next.js 16.3.4, sharp 0.35.4, and Vite 8.0.13. These versions intersect published security-advisory ranges:

- Next.js has a Node `ImageResponse` advisory fixed in 16.3.6. This source tree does not use `next/og` or `ImageResponse`, and production uses a Cloudflare Worker runtime. No reachable exploit of that advisory was established. [Maintainer advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j).
- A newer image-processing advisory lists Next.js through 16.4.0 and recommends sharp 0.35.5+ as a workaround. The app uses local `<img>` assets, and no active Next image-optimization route was established in this audit. Upgrade compatible pins and verify the Vinext build before adopting image optimization. [Maintainer advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw).
- Vite 8.0.13 falls within the affected range of an October development-server filesystem advisory. Exploitation requires additional path/import and server-exposure conditions; those conditions were not demonstrated here. The advisory lists patched 8.1.6, 8.2.4, and 8.3.3 branches. [Maintainer advisory](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22).

The full `npm audit` request failed with DNS resolution of `registry.npmjs.org`. This is a partial dependency review, not a clean vulnerability-scan result.
