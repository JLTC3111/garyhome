# Rental price ranges

The listing editor accepts independent **USD From/To** and **VND From/To** prices. Staff can enter either currency or both, with a fixed price or a range in each. All labels, help text and validation messages support English and Vietnamese. The heading follows the listing's month, week or night price period.

Enter From only for a fixed price, both amounts for a range, or leave both currencies empty for price on request. Each To amount requires a From amount in the same currency and must be at least that From amount. VND uses whole đồng. Equal endpoints display as a fixed price. Existing listing prices are preserved.

`properties.price` and `price_max` remain USD. Nullable `price_vnd` and `price_vnd_max` store independent VND quotes. Database constraints reject upper-only, reversed, negative and nonfinite ranges. Existing staff write permissions and public read policies apply to the new columns. Structured data publishes only entered quotes, including both currencies when supplied, using the [Schema.org price specification range fields](https://schema.org/UnitPriceSpecification).

Visitors choose USD or VND in the header's combined language and currency menu, search form, or property detail page. The header uses a globe icon with a translated tooltip that includes the current language and currency, and remains outside the hamburger navigation on mobile. Currency choices use navy and pale blue-gray to distinguish them from the sage language selection. Header links explicitly identify Customer Login and Staff Login, with Vietnamese equivalents. Language and currency apply immediately and persist independently in cookies and browser storage. Currency preferences sync across tabs and remain independent of authentication. An entered quote in the chosen currency always takes precedence. If it is absent, the other quote is converted and marked **≈**. If no usable rate is available, the entered currency remains visible and is explicitly identified. Listings without either quote show price on request.

The Vinhomes homepage cards and `/vinhomes` collection page use the same price component and conversion rules as ordinary listing cards, detail pages, related rentals, favourites and saved homes. Their supplied VND quotes remain the source amounts; USD displays are approximate conversions. Vinhomes also has a currency selector beside the collection introduction. The homepage budget shortcut displays in the visitor's currency while its URL explicitly preserves the original USD budget, preventing a currency change from reinterpreting the search amount.

Monthly budget filters match overlapping ranges in the currency saved with the search URL. Changing currency converts the displayed budget bounds with outward rounding; an unavailable conversion keeps their original units. Price sorting uses the starting amount in the selected currency. The Studio always shows entered prices rather than estimates.

Conversions use the USD selling rate from [Vietcombank's official rates page](https://www.vietcombank.com.vn/KHCN/Cong-cu-tien-ich/Ty-gia), which links to the public XML feed at `https://portal.vietcombank.com.vn/Usercontrols/TVPortal.TyGia/pXML.aspx`. If that feed is unavailable or invalid, the server uses the [free ExchangeRate-API endpoint](https://www.exchangerate-api.com/docs/free) at `https://open.er-api.com/v6/latest/USD`. The footer identifies the source actually used, labels the bank selling rate, and shows its update date in Vietnam time. Staff-entered prices always take precedence over conversion estimates.

Both sources use fixed HTTPS URLs. No visitor information, auth headers, cookies or API keys are sent. Requests have a three-second deadline per source covering the response body, accept at most 64 KiB, and reject redirects by using manual redirect mode and checking the HTTP status. This works on both Cloudflare and Next.js; Cloudflare rejects `redirect: "error"`. XML parsing extracts only the bank timestamp and a single valid USD selling quote, rejects DTDs and entities, and never resolves external XML resources. Validation checks the base currency where supplied, finite positive VND rates, expected timestamps, future dates and a maximum rate age of 72 hours.

The framework caches the bank feed for five minutes, respecting its published request-frequency guidance, and the daily backup for 24 hours. Each server process coalesces concurrent requests and throttles refresh attempts to five minutes, including failures. A previous valid rate can remain available for up to 72 hours; after that, conversions stop. `/api/exchange-rate` exposes only the sanitized USD/VND rate and source metadata used by this site, with no configurable upstream URL or cross-origin API access. Development-only failure diagnostics help distinguish fetch incompatibilities from provider outages. Open pages refresh every five minutes and invalidate expired rates during outages. The feed supplies reference estimates, not guaranteed settlement quotes.

The early language bootstrap intentionally adds `data-language-pending` to the root element when an older browser-only preference differs from the server cookie. Hydration suppresses only the root attribute warning; the provider settles the preference and removes that temporary attribute before paint.
